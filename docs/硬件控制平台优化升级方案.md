# 硬件控制平台优化升级方案

## 1. 文档定位

本文档用于指导后续大模型或开发人员对 `HZCYKJTHardWare` 平台进行小步、可验证、可回退的优化。

本文档不是一次性重构方案，也不是要求一个执行者在单次任务中完成全部修改。后续执行时必须按任务卡逐项实施，每次只处理一个明确目标，完成编译、测试和进度记录后再进入下一项。

当前系统边界：

```text
Delphi7 / x86 第三方程序
        ↓
C/C++ 32 位 DLL（extern "C"、__stdcall、x86 Release）
        ↓ Loopback HTTP
C# Proxy（Windows UI + Hardware Service Layer）
        ↓ LAN HTTP / MJPEG / RTSP
终端及车牌相机
```

部署基线：

- Windows 10 x64。
- 第三方调用方为 Delphi7 x86。
- DLL 必须保持 x86 Release 和现有 C ABI。
- Proxy 生产部署目标为 x86 Release，运行环境为 .NET Framework 4.8。
- 当前 Proxy 项目实际 `TargetFramework` 为 `net46`；是否改为 `net48` 必须作为独立任务评估，不能夹带在其他优化中。
- 系统目标是 24×7 运行，并能够完成 24 小时、72 小时、7 天和 30 天分级验证。

## 2. 已确认的产品与技术决策

### 2.1 日志信息保留原则

本项目运行在内网环境，业务身份信息不作为本轮日志优化的限制条件。

允许在有明确诊断价值的请求和回调日志中保留完整的标量业务信息，例如：

- 姓名。
- 证件号码。
- 证件类型。
- 出生日期。
- 国籍或地区代码。
- MRZ。
- NFC 卡片完整文本。
- 授权请求和授权结果中的业务字段。
- OCR 返回的结构化文本字段。

禁止或限制记录的内容：

- 完整 Base64 图片。
- 完整图片 Buffer、二进制帧或视频数据。
- 逐帧或逐包内容。
- 包含 Base64 的完整大 JSON 原文。
- 无长度上限的终端响应正文。
- 密码、Token、RTSP/HTTP URL 中的认证凭据。该项属于系统凭据保护，不属于个人隐私限制。

如确实需要记录原始 JSON，必须先执行载荷清理：

```text
1. 将 image_base64、imageData、image_data、undistorted_image_base64 等大字段替换为：
   <omitted type=base64 chars=123456>
2. 保留其他标量业务字段。
3. 单条日志设置最大长度，建议默认 8 KB，超出时标记原始长度和截断状态。
4. 禁止为了打印日志而复制完整图片或 Base64 字符串。
```

### 2.2 虹膜预览技术方向

虹膜预览改为与人脸、指纹预览一致的 Proxy 外部预览方式：

```text
第三方 HWND
   ↑
Proxy MjpegPreviewController 直接绘制
   ↑
终端 HTTP MJPEG
```

目标状态：

- DLL 不再获取虹膜 URL 后自行创建 native libVLC Renderer。
- DLL 的 `HZCYKJTHardWare_StartIrisPreview` 和 `StopIrisPreview` 导出函数签名、返回值和第三方调用方式保持不变。
- DLL 通过现有 `/preview/iris/start`、`/preview/iris/stop` IPC 让 Proxy 管理虹膜 MJPEG 会话。
- Proxy 继续通过 `/preview-ready` 向 DLL 通知预览启动成功或失败。
- 虹膜预览纳入 Proxy 的会话管理、断流恢复、终端切换、Proxy 重启恢复和有序退出。
- native DLL 旧虹膜 VLC 路径在第一阶段保留为可回退代码，不立即删除；完成实机和长稳验证后再单独决定是否清理。

## 3. 总体优化目标

### 3.1 稳定性目标

- 消除可能导致崩溃、未定义行为、死锁和永久阻塞的 P0 风险。
- 所有后台线程、Timer、Socket、HttpClient、VLC/MJPEG 对象均有明确 Owner。
- 服务停止后不得遗留继续访问已释放依赖的旧工作线程。
- 第三方 callback 阻塞、异常或重入不能拖垮 Proxy。
- 单个终端离线不能导致请求无限堆积、线程池耗尽或日志风暴。
- 单路视频异常不能影响 OCR、NFC、授权、抓拍和其他视频会话。

### 3.2 日志目标

- 仅查看 INFO、WARN、ERROR 即可完成大部分现场初步排查。
- 同一 RequestId 可以贯穿第三方边界、DLL、Proxy、终端请求和 callback 投递。
- 正常运行日志简洁；异常日志能够说明失败阶段、终端、错误码和耗时。
- 允许保留有诊断价值的完整业务标量信息。
- Base64、图片、帧和大载荷不进入日志。
- 日志写入异常不能阻塞或拖垮业务。
- 日志文件必须同时具备按天、按大小滚动和总量清理，不能写满系统盘。

### 3.3 架构目标

- UI 和 DLL 请求继续复用同一套 `BizOperationHandler`、Terminal、Preview、Registry 和 Coordinator。
- 不为追求形式上的架构完整而引入大型框架。
- 通过轻量 `OperationContext` 统一 RequestId、Operation、Terminal、Deadline、CancellationToken 和日志上下文。
- 逐步形成每终端独立的 `DeviceSession`，但不立即引入 Actor Framework。

## 4. 不可突破的约束边界

后续执行者未经明确确认不得修改以下内容：

### 4.1 DLL ABI

- 不改变 DLL 导出函数名。
- 不改变现有参数数量、顺序和类型。
- 不改变 `__stdcall` 调用约定。
- 不删除 `extern "C"`。
- 不改变现有结构体字段顺序、类型和 `#pragma pack`。
- 不改变现有 callback 函数签名。
- 不改变现有错误码数值。
- 不改变既有接口 `1/0` 返回语义。
- `SaveLatestPlateFrame` 的负错误码语义保持不变。

允许在单独确认后新增向后兼容的导出函数，但不得把新增函数作为修复既有接口的强制前提。

### 4.2 第三方行为

- Delphi7 现有调用代码应继续工作。
- 第三方 HWND 的所有权仍属于第三方，Proxy/DLL 只能借用，不能销毁。
- callback JSON 已存在字段的含义不得改变。
- 不要求第三方为了内部优化更改调用顺序或增加新依赖。
- `InitSdk → RegisterEventCallback → StartProcess → 业务调用 → EndProcess → ReleaseSdk` 主流程保持兼容。

### 4.3 Proxy 与终端协议

- 不擅自修改终端已有 HTTP 路径和字段含义。
- 不擅自改变终端 callback 的 HTTP 状态码语义。
- 如需改变 callback 的 ACK 时机或重试策略，必须先确认终端的超时、重复投递和重试行为。
- 新配置项必须提供与当前行为兼容的默认值。
- 未经确认不得引入 SQLite、消息队列或其他新依赖。

### 4.4 开发过程

- 不得大规模重写 `ProxyServer`、`MainForm` 或 `exports.cpp`。
- 不得在一个任务中同时处理多个 P0/P1 问题。
- 不得删除旧逻辑作为第一步；优先保留回退开关或旧分支。
- 不得覆盖用户已有未提交修改。
- 每次扩大文件范围、改变协议或引入依赖前必须暂停确认。

## 6. 优化阶段与任务卡

## 阶段 1：P0 生命周期与线程安全

### S1：修复 native 单例并发初始化

目标：

- 消除 `PreviewManager` 和 native `TerminalManager` 首次并发访问的数据竞争。

主要文件：

- `src/preview_manager.cpp`
- `src/terminal_manager.cpp`
- 对应头文件和单元测试文件。

修改方向：

- 优先采用 C++11 函数局部静态实例，或保持进程生命周期不析构的函数局部静态指针。
- 如必须保留动态构造，使用 `std::call_once`。
- 不改变任何公共 ABI。

验证：

- x86 Release 编译。
- 多线程并发首次调用预览和终端接口。
- 重复 Init/Release。
- 现有 Delphi Demo 回归。

回退：恢复原单例实现即可，不涉及数据迁移。

### S2：加固第三方 callback 生命周期

目标：

- 防止 callback 替换、Release 或 DLL 卸载期间调用失效函数指针。
- 记录 callback 执行耗时和阻塞状态。

主要文件：

- `src/event_dispatcher.cpp`
- `src/event_dispatcher.h`
- `src/exports.cpp`
- `include/HZCYKJTHardWare.h`

修改方向：

- 增加 callback generation 和 in-flight count。
- 更换 callback 时等待旧 generation 的在途调用结束，必须有超时和明确失败结果。
- 保持“不能在 callback 线程内调用 `ReleaseSdk`”的保护。
- callback 执行超过阈值时记录 WARN，例如 500ms；正常成功降为 DEBUG。
- 暂不改变 callback 签名。
- 是否允许 `RegisterEventCallback(nullptr)` 作为注销行为，属于外部行为变化，必须单独确认。

验证：

- callback 正常返回、抛出 SEH、阻塞、重入。
- callback 执行期间重复注册。
- callback 执行期间调用 Release。
- callback 返回后成功 Release 和 FreeLibrary。

### S3：避免服务停止后遗留业务 Worker

目标：

- `QueueManager.Dispose` 后不存在继续使用已释放依赖的旧 Worker。
- 停止失败时禁止在同一进程直接启动新的 ProxyServer 实例。

主要文件：

- `Core/WorkerQueue.cs`
- `Core/QueueManager.cs`
- `Server/Runtime/ProxyRuntime.cs`
- `Server/ProxyServer.cs`
- `MainForm.cs`

修改方向：

- 为 QueueTask 增加明确的 operation deadline/cancellation context。
- 所有实际 HTTP handler 必须消费 CancellationToken。
- 对无法取消的 native 调用，停止超时后把服务标记为 `FaultedNeedsProcessRestart`。
- `FaultedNeedsProcessRestart` 状态下不允许 UI 原地重新启动服务。
- 不使用 `Thread.Abort`。

验证：

- 模拟 handler 永久阻塞。
- 停止服务后检查旧线程、Socket、HttpClient 访问。
- 停止超时时 UI 给出明确提示，不创建第二套服务。

### S4：修复启动事务与回滚

目标：

- Proxy 任一监听器或后台组件启动失败时，完整反向回滚。

主要文件：

- `Server/ProxyServer.cs`
- `Server/Runtime/TransportLayer.cs`

修改方向：

- `_started` 只在全部组件成功启动后置位。
- 记录已完成启动的组件列表，catch 中逆序停止。
- 失败后允许安全重试；如回滚失败则进入 Faulted 状态。

验证：

- DLL 监听端口占用。
- 终端 callback 端口占用。
- 第二个 listener 启动失败。
- 后台指标或健康检测启动异常。

## 阶段 2：虹膜 MJPEG 统一

### V1：DLL 虹膜预览迁移到 Proxy

目标调用链：

```text
HZCYKJTHardWare_StartIrisPreview(hwnd)
    ↓
DelphiProxy.StartIrisPreview(requestId, hwnd, callbackUrl)
    ↓
POST /preview/iris/start
    ↓
DllCommandHandler.HandlePreviewStart(Iris)
    ↓
PreviewManager.StartPreview(External)
    ↓
MjpegPreviewController
    ↓
第三方 HWND
```

当前可复用能力：

- `DelphiProxy::StartIrisPreview` 和 `StopIrisPreview` 已存在。
- Proxy 已存在 `/preview/iris/start`、`/preview/iris/stop` 路由。
- `DllCommandHandler` 已将 Iris 交给统一 `HandlePreviewStart`。
- `PreviewManager` 已具备 External Session、MJPEG Controller、故障恢复和 `/preview-ready` 回调。

第一步修改范围：

- `src/exports.cpp`
  - `StartIrisPreviewBody` 改为与 Camera/Fingerprint 相同的 Proxy 外部预览模式。
  - `StopIrisPreviewBody` 改为调用 `DelphiProxy::StopIrisPreview`。
  - 保留 request_id、HWND、running lease 和现有返回值语义。
- `src/exports.cpp` 的外部预览租约快照和 Proxy 实例恢复逻辑。
  - 将 Iris 纳入 `ExternalPreviewLeaseMonitor` 的快照、停止和恢复。
- `src/delphi_proxy.cpp/.h`
  - 只补齐 timeout、日志和错误映射的一致性，不改变现有路径。
- Proxy 预览测试。
  - 增加 Iris External MJPEG Start/Stop/Restart/Switch 测试。

第一步不做：

- 不删除 DLL `PreviewManager`。
- 不删除 `LibVlcRtspRenderer`。
- 不影响车牌和其他可能仍依赖 native VLC 的路径。
- 不改变公开 Iris API。

必须保持的行为：

- 无效 HWND 返回失败。
- 重复启动返回“已运行”语义。
- Start 接口仍表示请求已受理，最终状态通过原 callback 通知。
- Stop 必须幂等地清理 DLL lease 和 Proxy Session。
- 终端切换期间必须拒绝旧代次启动或取消旧会话。
- Proxy 重启后，仍有效的第三方 HWND 应能恢复虹膜预览。
- 第三方进程退出、HWND 失效后不得继续恢复。

回退方案：

- 在验证阶段可使用内部配置或编译期分支保留 `dll_vlc` 旧模式。
- 默认目标模式为 `proxy_mjpeg`。
- 回退不得要求第三方修改调用代码。

验证矩阵：

| 场景 | 预期 |
|---|---|
| Start → Stop | 线程、Socket、HWND 释放 |
| Start → Stop → Start 1000 次 | 无线程、Handle 和内存持续增长 |
| MJPEG 断流 | 自动重连或发出最终失败 callback |
| 终端 1→2 切换 | 旧流停止，新终端流恢复 |
| Proxy 重启 | DLL lease monitor 恢复有效会话 |
| 第三方 HWND 销毁 | 会话停止，不再恢复 |
| Proxy 退出 | MJPEG reader/render 线程正常退出 |
| DLL Release | 先通知 Proxy 停止，再清理 callback 和 IPC |

## 阶段 3：日志体系优化

### L1：统一日志上下文和字段

推荐格式：

```text
[yyyy-MM-dd HH:mm:ss.fff][Level][Module][Operation][Device][RequestId] Message Key=Value
```

统一字段：

- `Operation`
- `TerminalIndex` 或设备名称。
- `RequestId`
- `Result`
- `ErrorCode`
- `DurationMs`
- `QueueWaitMs`
- `Attempt`
- `RouteEpoch`

业务请求至少输出两条 INFO：

```text
入口：收到第三方或 UI 请求
出口：最终成功或最终失败
```

中间 HTTP、队列、路由和内部步骤使用 DEBUG。

### L2：载荷记录策略

允许 INFO 记录：

- 授权请求完整标量字段。
- OCR 识别出的姓名、证件号、MRZ 等字段。
- NFC 完整卡片文本。
- callback 的业务状态、错误码、设备和路径。

推荐示例：

```text
[INFO][Authorization][Submit][T1][REQ-001]
Name=张三 IdNo=1234567890 DocType=01 Nationality=CHN Sex=M Birthday=19900101

[INFO][NfcRead][Complete][T1][REQ-002]
Result=Success CardText=完整NFC文本 DurationMs=283
```

Base64 等大字段只能记录摘要：

```text
[DEBUG][OcrCallback][Payload][T1][REQ-003]
card_type=30 name=张三 image_base64=<omitted chars=438921> raw_json_chars=445102
```

实现方向：

- 提供统一 `SanitizeLargePayloadForLog` 或等价工具。
- 按 JSON key 过滤，而不是用简单字符串截断后再打印。
- 输出省略字段的字符数或估算字节数。
- 日志过滤失败时只能输出 payload 长度和 RequestId，不能回退到完整正文。

### L3：级别调整

INFO：

- 应用、Proxy、DLL 启动和退出。
- 终端选择、上线、离线和恢复。
- 流程开始和结束。
- 抓拍、OCR、NFC、授权请求和最终结果。
- 视频开始、停止、恢复成功和最终失败。
- callback 最终投递成功或永久失败。

WARN：

- 首次超时、暂时离线、准备重试。
- 视频断流和准备恢复。
- 队列接近容量或任务排队超时。
- 第三方 callback 执行过慢。
- callback 来源不匹配、重复或已过期。

ERROR：

- 操作最终失败。
- 恢复次数耗尽。
- IPC 最终不可用。
- 资源初始化或释放失败。
- 服务进入 Faulted/NeedsRestart。
- callback 永久投递失败。

DEBUG：

- HTTP 开始/结束及状态码。
- 队列内部步骤。
- route epoch 和 Session 关联。
- VLC/MJPEG 内部启动阶段。
- 健康检查普通成功。

TRACE：

- 仅用于逐帧、逐包和高频协议调试。
- 生产默认关闭。
- 如果没有实际逐帧诊断需求，可以暂不实现 TRACE，不能把逐帧日志放入 DEBUG。

### L4：日志限频和聚合

以下日志必须按设备、接口、错误码组合限频：

- 12029、连接拒绝、连接超时。
- 终端持续离线。
- MJPEG/VLC 连续重连失败。
- callback listener busy。
- 无效或重复 callback。
- 日志写入异常。

建议行为：

```text
第一次失败立即记录。
同类失败在 60 秒窗口内计数。
窗口结束输出：Count、FirstTime、LastTime、LastError。
恢复时立即输出一次 INFO。
```

### L5：日志文件可靠性

目标：

- Proxy Logger 保持有界异步写入。
- DLL Logger 避免在业务线程内长期同步磁盘 I/O。
- ERROR 不因普通 DEBUG/INFO 队列饱和而无提示丢失。
- 同时支持按天和按大小滚动。

建议默认值：

```text
retention_days = 30
max_total_size_mb = 2048
max_file_size_mb = 100 或 200
disk_warning_free_mb = 2048
```

必须处理：

- 当前日文件也计入容量治理。
- 日志目录不可写时使用应急文件或 `OutputDebugString`，且不能向业务抛异常。
- 低磁盘时停止 DEBUG，必要时聚合 INFO/WARN，但 ERROR 仍应尽力保留。
- 记录 `log_pending`、`log_dropped_total`、`log_write_failures`、当前文件大小和最后成功 flush 时间。

## 阶段 4：网络与 Callback 可靠性

### N1：修复 DLL CallbackServer HTTP 分片

- 循环读取直到完整 `\r\n\r\n`。
- 设置 header 最大值。
- 严格校验 `Content-Length`。
- 正文未读满时返回失败，不能交给 EventDispatcher。
- 处理 partial send。
- `inet_pton` 失败必须关闭 Socket 并返回配置错误。

### N2：修复 WinHTTP 截断响应误判成功

- `WinHttpQueryDataAvailable` 或 `WinHttpReadData` 失败立即返回失败。
- 增加响应正文最大值。
- 日志记录 Windows Error、URL 摘要、RequestId 和已读取长度。

### N3：Proxy HTTP 内存与完整性

- 完整校验正文实际读取长度等于 `Content-Length`。
- DLL 命令和终端 callback 使用不同的 body 大小上限。
- 对包含图片的 callback 评估减少 `MemoryStream → ToArray → byte[] → string` 多次复制。
- 并发内存预算按 x86 进程计算，不能只看单请求 16 MB 限制。

### N4：Callback ACK 与投递可靠性

在修改前先确认终端：

- callback 超时时间。
- 非 2xx 是否重试。
- 重试次数和间隔。
- 是否可能重复投递。

可选方案：

| 方案 | 行为 | 适用场景 |
|---|---|---|
| A | 完成解析、保存和 DLL 投递后返回 2xx | 终端支持较长等待和非 2xx 重试 |
| B | 有界内存 outbox，快速 ACK | 允许 Proxy 崩溃时丢未投递事件 |
| C | 持久化 outbox 后 ACK | callback 业务结果不允许因 Proxy 重启丢失 |

未经确认不得直接引入方案 C 或新的数据库依赖。

## 阶段 5：设备状态与故障恢复

### D1：每终端状态快照

在现有 `TerminalManager` 上先增加轻量状态：

```text
TerminalIndex
BaseUrl
OnlineState
LastSuccessUtc
LastFailureUtc
ConsecutiveFailures
CircuitState
CurrentProcessRequestId
ActiveOperationCount
LastHealthSnapshot
```

第一阶段只增加内部状态和指标，不改变外部 API。

### D2：终端 Circuit Breaker

- 连续网络失败达到阈值后进入 Open。
- Open 状态普通业务快速失败，健康探测继续低频运行。
- 探测成功进入 HalfOpen，再恢复 Closed。
- 切换终端和人工请求健康检查可以触发提前探测。
- 不能把业务错误、参数错误误判为终端离线。

### D3：Proxy 进程级恢复

- 明确 Proxy 崩溃后的启动责任：DLL、Windows 任务计划、服务管理器或外部 Watchdog。
- 不建议 DLL 在每次普通请求失败后立即杀进程重启，避免重启风暴。
- Proxy 重启后依赖 instance id 和有效 HWND 恢复外部预览。

## 阶段 6：视频与 x86 性能

### P1：车牌最新帧

- 当前 200ms 临时文件快照属于高频磁盘路径。
- 优先评估 libVLC 内存 callback 或独立帧缓存。
- 如果短期不能改为内存路径，降低刷新频率，并只在存在取帧需求时启用。
- 保持 `SaveLatestPlateFrame` 的原子保存和错误码兼容。

### P2：MJPEG 帧分配

- 统计单帧大小、FPS、Gen2 GC、Private Bytes 和 LOH。
- 评估复用读取 Buffer、帧 Buffer Pool 和减少帧复制。
- `Image`、`Graphics`、HDC 仍必须在当前帧内严格释放。
- 不为减少分配而跨线程共享可变 `Image` 对象。

### P3：VLC native 分配

- 所有 `Marshal.AllocHGlobal`、`StringToHGlobalAnsi` 使用 `try/finally`。
- media/player/instance 的失败路径逐层释放。
- Stop timeout 后记录 live thread、native state 和 NeedsRestart。
