### 重要注意事项

- 本程序连接的是采集终端和相关预览/回调服务，不是闸机安全控制台。当前界面未发现闸机开关、放行或道闸控制按钮。
- 只有看到明确的成功日志、预览画面或最终回调结果，才能认为操作完成。按钮可点击不等于设备已经就绪。
- `授权测试` 会发送程序内置的测试参数，不是可编辑的生产授权录入界面。生产环境使用前必须由项目负责人确认。
- 不要在任务进行中随意切换终端、重复点击同一按钮、断开网络或关闭设备电源。
- 日志、OCR 结果和识别图片可能包含证件号码、姓名、卡号等敏感信息，只能发送给授权的技术人员，并应先脱敏。

## 2. 程序简介

本程序用于在第三方业务程序、采集终端和本地硬件服务之间提供统一的操作入口。当前代码显示的主要链路为：

```text
第三方程序 / DLL → 本地 Proxy 服务 → 采集终端 → 回调结果 → Proxy / DLL / 第三方程序
```

Proxy 负责：

- 提供本机 DLL 请求监听和终端回调监听；
- 选择当前操作终端（左通道或右通道）；
- 向当前终端发起流程、抓拍、OCR、IC 卡、虹膜和授权请求；
- 管理摄像头、指纹、虹膜及三路车牌预览；
- 接收终端异步回调并保存图片、JSON 结果或向 DLL 转发事件；
- 显示终端硬件健康状态、运行状态和操作日志。

程序启动后通常按“启动服务 → 检查硬件状态 → 选择终端 → 开始流程 → 执行采集/识别 → 确认结果 → 停止预览 → 结束流程 → 安全退出”的顺序使用。

## 3. 使用前准备

### 3.1 程序目录与依赖

操作人员不得自行整理或删除程序目录。当前 Proxy 工程明确依赖以下内容：

| 内容 | 用途 | 操作要求 |
| --- | --- | --- |
| `HZCYKJTHardWare.Proxy.exe` | 主程序 | 必须保留 |
| `HZCYKJTHardWare.Proxy.json` | Proxy 的监听、终端、预览和保存配置 | 必须与程序放在发布包规定位置；不要在运行中手工修改 |
| `HZCYKJTHardWare.json` | DLL 与 Proxy 协同使用的配置文件名；具体部署方式取决于发布包 | 是否与 Proxy 放在同一目录需项目负责人确认 |
| `Newtonsoft.Json.dll`、`System.ValueTuple.dll` 等 .NET 依赖 | 程序运行依赖 | 必须保留 |
| `vlc` 目录及其插件 | VLC/RTSP 预览运行依赖 | 使用需要 VLC 的预览时必须保留，不能被安全软件隔离 |
| `HZCYKJTHardWareExe_Logs` | Proxy 文件日志目录 | 不要手工改名或移动正在写入的日志 |
| `captures` | 默认图片和识别结果目录 | 需要保证目录可写、磁盘空间充足 |

### 3.2 网络和终端

当前 Proxy 配置文件中的默认值为：

| 项目 | 当前配置值 | 说明 |
| --- | --- | --- |
| DLL 监听 | `127.0.0.1:18080` | 供本机 DLL 请求使用 |
| 终端回调监听 | `0.0.0.0:18081`，路径 `/terminal-callback` | 终端回调 Proxy 使用；终端必须能访问本机地址 |
| 终端 1 | `http://192.168.20.30:9098` | 界面显示为“终端 1 / 左通道” |
| 终端 2 | `http://192.168.20.31:9098` | 界面显示为“终端 2 / 右通道” |
| 默认保存目录 | `程序目录\\captures` | 配置值为 `./captures`，代码实际按绝对路径使用 |

以上地址是当前仓库配置事实，不代表所有现场部署地址。若现场配置不同，以交付目录中的配置文件和项目负责人确认结果为准。

启动前确认：

1. 终端设备已通电，网络链路正常，目标终端可达；
2. 终端所需采集模块处于可用状态，没有被其他程序占用；
3. 本机 `18080`、`18081` 或现场配置的端口未被其他程序占用；
4. 防火墙允许终端访问本机回调端口；
5. `captures` 目录所在磁盘有足够空间；
6. 不要重复启动多个 Proxy 实例。程序使用单实例互斥，重复打开会提示“程序已在运行，请勿重复打开”。

### 3.3 权限和启动顺序

- 代码没有主动申请管理员权限。是否需要管理员权限取决于安装目录权限、防火墙策略和现场安全策略，需项目负责人确认。
- 推荐顺序：先确认终端与网络，再启动 Proxy；如果第三方程序依赖 DLL 自动连接 Proxy，再启动第三方程序并确认其回调注册成功。
- Proxy 主窗口加载完成后会自动尝试启动本地服务。若服务已停止，可在界面点击“启动服务”。

### 4.2 硬件健康检测区

界面标题为“硬件健康检测”，包含“刷新状态”按钮及五类设备卡片：`OCR 文字识别`、`IC 卡`、`指纹设备`、`虹膜设备`、`人脸设备`。

| 控件/状态 | 功能说明 | 操作方式和完成标志 | 失败处理 |
| --- | --- | --- | --- |
| 刷新状态 | 立即请求当前终端硬件状态 | 服务运行后点击一次；摘要更新并且各卡片显示状态 | 看到“检测失败 · 终端连接失败或超时”时，检查网络、终端和日志 |
| 正常 | 设备在线且可服务 | 卡片显示“✓ 正常 / 设备连接稳定” | 可继续对应操作 |
| 启动中 | 设备正在启动或自动恢复 | 等待状态变为正常 | 不要连续发起对应任务 |
| 离线 | 设备未响应或连接中断 | 停止对应采集，先检查设备和网络 | 不能把离线状态下的按钮可点击理解为可用 |
| 异常 | 设备报告故障或自动恢复失败 | 停止对应操作并联系技术人员 | 提供检测时间、设备名称、提示和日志 |
| 待检测 | 服务刚启动、终端未上报或未包含该设备 | 点击“刷新状态”并等待 | 持续待检测时联系技术人员 |

健康检测通常每 5 分钟自动轮询一次；异常时会按较短间隔进行有限复查。健康状态只说明终端上报状态，不代表业务结果或人员通行安全结论。

## 5. 标准操作流程

### 5.1 程序启动

1. 从交付目录启动 `HZCYKJTHardWare.Proxy.exe`。
2. 若提示“程序已在运行，请勿重复打开”，关闭重复启动动作，使用已有实例。
3. 主窗口加载后，确认顶部为“● 运行中”。程序会自动尝试启动服务。
4. 查看“DLL 监听”“回调监听”“当前终端”是否显示具体值，而不是“配置读取失败”。
5. 查看“硬件健康检测”：服务启动后等待卡片从“待检测”更新为实际状态，必要时点击“刷新状态”。
6. 若服务未启动，点击“启动服务”一次并观察日志。若仍失败，记录错误文本和时间，不要反复点击。

### 5.2 终端选择

1. 先确认服务运行、当前没有切换或采集请求。
2. 需要左通道时点击“左通道”，需要右通道时点击“右通道”。
3. 以顶部“当前终端”文字和日志中的切换结果为完成标志。
4. 切换后，后续流程、抓拍、OCR、IC 卡、虹膜和授权请求都会作用于新终端。
5. 如果出现“终端切换中”“切换失败”或超时，等待当前日志完成；不要立即连续点击两个通道按钮。

特别注意：当前程序对切换期间的排队请求有保护逻辑，旧终端的过期回调可能被丢弃。为避免结果归属错误，采集过程中不要切换终端。

### 5.3 开始和结束业务流程

1. 服务运行且目标终端健康后，点击“开始流程”。
2. 等待日志显示 `开始流程: OK`，并确认“开始流程”按钮处于活动状态。
3. 按需进行预览、抓拍、OCR、IC 卡、虹膜或授权测试。
4. 每次异步操作等待最终回调、保存路径或失败信息后，再执行下一次相同业务。
5. 所有业务结果已确认、预览已停止后，点击“结束流程”。
6. 以日志显示 `结束流程: OK` 且开始流程按钮恢复普通状态为完成标志。

### 5.4 预览

1. 在预览设备下拉框选择一个资源。
2. 点击“开始预览”一次，等待对应画面出现。
3. 画面出现后，提示区应显示该资源“预览中”，按钮不应再允许重复启动。
4. 预览异常时先点击“停止预览”，确认占位提示恢复后再尝试启动一次。
5. 业务结束或退出前，逐一选择正在预览的资源并点击“停止预览”。
6. 关闭预览承载窗口或切换终端前，必须先停止相关预览；若现场需要切换终端，应在无采集请求时进行。

### 5.5 抓拍

#### 人脸抓拍

1. 确认当前终端为目标终端，设备健康状态为“正常”，流程已开始。
2. 确认人员位于摄像头有效区域、光线和姿态满足现场要求。
3. 点击“人脸抓拍”一次。
4. 等待日志出现成功保存或明确失败信息。成功时以保存路径/成功日志为准，不以按钮点击为准。

#### 指纹抓拍

1. 确认指纹设备为“正常”，手指按现场要求放置并保持稳定。
2. 点击“指纹抓拍”一次。
3. 等待主指纹图保存成功；如终端返回无畸变数据，日志或目录中还会出现无畸变 BMP。
4. 失败时先移开手指、等待上一次请求结束，再按现场流程重试；不要连续高速点击。

### 5.6 OCR、IC 卡和虹膜识别

- OCR：放置证件后点击“OCR 阅读”，等待“识别成功/失败”回调。成功时检查识别摘要和保存目录；必要时由授权人员查看 `ocr_result.json`、`MRZ.json` 和证据图片。
- IC 卡：按设备要求放置 IC 卡，点击“IC 卡识别”，等待卡片成功/失败回调。卡片信息可能出现在日志或第三方回调中，不应把卡号复制到非授权位置。
- 虹膜：确认虹膜设备和预览状态正常，按现场要求定位后点击“虹膜抓拍”，等待最终回调和保存路径。左右眼图片是否都生成以日志和目录实际文件为准。

### 5.7 授权测试

1. 只有项目负责人明确允许在当前环境测试时，才可点击“授权测试”。
2. 确认当前终端和业务环境正确，避免把测试请求发送到生产终端。
3. 点击一次后，等待日志中的“授权已下发”或失败信息，再等待终端最终授权回调。
4. 授权结果只能以最终回调为准；不能通过修改日志或手工修改结果文件改变授权结论。
5. 若授权超时、字段不完整或结果异常，停止继续点击并联系技术人员。

### 5.8 正常结束

1. 等待当前抓拍、OCR、IC 卡、虹膜和授权任务完成或明确失败。
2. 停止全部正在运行的预览。
3. 点击“结束流程”，确认日志成功。
4. 如不再需要 Proxy 服务，点击“停止服务”，确认顶部显示“● 已停止”。
5. 关闭窗口时选择“退出程序”。如果选择“最小化到托盘”，程序不会退出，不能把它当作停机完成。

推荐关闭顺序：第三方业务程序停止发请求 → 停止预览 → 结束流程 → 停止 Proxy 服务（如需要）→ 退出 Proxy。

## 6. 功能边界与禁止事项

### 6.1 程序负责的功能

- 提供本地 DLL 请求监听和终端回调监听；
- 管理左右两个配置终端的当前路由；
- 发起和结束业务流程；
- 发起人脸、指纹、虹膜抓拍；
- 发起 OCR 和 IC 卡识别；
- 发起当前界面提供的授权测试请求；
- 启停摄像头、指纹、虹膜和三路车牌预览；
- 展示硬件健康状态和运行指标；
- 保存代码已实现的图片、OCR JSON、MRZ JSON 和日志。

### 6.2 程序不负责的功能

- 不负责修复终端内部硬件、传感器、摄像头或读卡器的物理故障；
- 不负责修改第三方业务数据库或人工纠正识别结果；
- 不负责闸机开关、人员放行、通道安全联锁等当前界面未实现的控制；
- 不保证网络中断、终端离线、设备忙或超时情况下请求一定成功；
- 不负责处理未在当前协议和代码中定义的第三方请求；
- 不应由操作人员直接修改 DLL、Proxy、VLC 或核心配置文件。

### 6.3 操作限制

- Proxy 不允许多开；重复启动会被单实例互斥拦截。
- 运行中不允许手工修改配置文件；修改后应按维护流程重启并验证。
- 不允许在任务进行中切换终端、关闭预览宿主窗口、结束进程、拔出设备或断开网络。
- 不允许频繁重复点击抓拍、识别、授权或预览按钮；遇到“设备忙”“请求超时”“服务忙”应先等待并查看日志。
- 不允许直接结束进程作为常规退出方式。只有在技术人员指导下，且已记录日志和任务状态后，才可处理无响应进程。
- 不允许绕过正常流程直接修改结果文件、回调数据或调用未公开的中间接口。
- 日志“清空”只清空界面，不代表磁盘日志或业务结果已删除。

### 6.4 数据边界

程序可能保存：人脸图、指纹图、无畸变指纹 BMP、虹膜图、OCR 原始 JSON、MRZ JSON、可见光/红外/紫外/人像证据图、IC 卡结果回调、授权回调和运行日志。

默认保存路径为程序目录下的 `captures`。当前配置启用按日期目录和请求编号目录组织，典型结构为：

```text
程序目录\captures\yyyyMMdd\request_id\结果文件
```

日志默认写入程序目录下的 `HZCYKJTHardWareExe_Logs`，文件名形如 `HZCYKJTHardWareExe_Logs_yyyyMMdd.log`。DLL 独立运行时还可能使用 `HZCYKJTHardWareDLL_Logs`，具体以实际交付包为准。

当前代码没有把“历史结果保留多久”作为操作人员可见设置；配置默认值存在，但现场保留期限、备份和删除策略仍需项目负责人确认。任何数据异常、误删或疑似泄露，应立即停止相关操作并联系技术人员。

## 7. 状态和提示说明

| 状态/提示 | 含义 | 是否继续操作 | 推荐处理 |
| --- | --- | --- | --- |
| `● 运行中` | Proxy 服务已启动 | 可以，但仍需检查终端健康状态 | 查看硬件健康检测和当前终端 |
| `● 已停止` | Proxy 服务未运行 | 不可以执行业务 | 点击“启动服务”一次并看日志 |
| `等待服务启动` | 健康检测尚未开始 | 暂缓设备操作 | 等待服务启动 |
| `待检测` | 终端尚未上报或刚启动 | 暂缓对应操作 | 点击“刷新状态”，持续不变则联系技术人员 |
| `正常` | 设备上报在线 | 可以执行对应功能 | 仍需遵循流程和设备摆放要求 |
| `启动中` | 设备正在初始化或恢复 | 暂缓对应功能 | 等待转为正常；不要连续点击 |
| `离线` | 设备无响应/断开 | 不要执行对应功能 | 检查电源、网络和终端状态 |
| `异常` | 设备故障或自动恢复失败 | 停止对应功能 | 保存日志和提示，联系技术人员 |
| `开始流程: OK` | 流程已被当前终端接受 | 可以继续业务 | 确认当前终端未被切换 |
| `结束流程: OK` | 流程结束成功 | 可以退出或切换 | 先确认预览已停止 |
| `预览中` | 所选预览已经启动 | 可停止，不要重复启动 | 观察对应画面 |
| `请求超时` / `timeout` | 在规定时间内未完成 | 暂停重复操作 | 检查网络、设备和日志 |
| `设备忙` / `busy` / `service_busy` | 同类任务或服务正在处理 | 不要重复点击 | 等待当前任务结束 |
| `terminal_switching` | 正在切换终端 | 暂停所有新请求 | 等待切换完成 |
| `preview_failed` | 预览地址、窗口或播放器启动失败 | 不要连续重试 | 停止一次，检查配置、VLC、网络和 HWND/窗口生命周期 |
| `程序正在退出` | 正在释放服务、预览和日志 | 不要操作 | 等待退出完成 |

## 8. 常见问题与异常处理

### 8.1 程序无法启动或提示重复运行

1. **现象**：双击后没有新窗口，或提示“程序已在运行，请勿重复打开”。
2. **可能原因**：已有 Proxy 实例在运行、程序正在托盘、文件被占用或运行依赖缺失。
3. **操作人员处理**：先查看任务栏和系统托盘；双击托盘图标恢复已有窗口。不要直接再开多个实例。
4. **联系技术人员条件**：确认没有已有实例仍无法启动，或启动后立即退出。
5. **提供信息**：发生时间、Windows 用户、程序目录、是否显示过提示、同目录日志文件。

### 8.2 服务启动失败或端口占用

1. **现象**：顶部仍为“● 已停止”，日志出现“启动服务失败”。
2. **可能原因**：端口被占用、配置文件格式错误、目录或日志不可写、防火墙策略阻断。
3. **操作人员处理**：确认没有重复 Proxy；检查网络和程序目录权限；点击“启动服务”只重试一次；记录错误信息。
4. **联系技术人员条件**：第二次启动仍失败，或需要修改端口/防火墙。
5. **提供信息**：日志时间、DLL 监听地址、回调监听地址、完整错误提示、是否刚更换配置。

### 8.3 硬件显示离线、异常或持续待检测

1. **现象**：健康卡片显示“离线”“异常”或“待检测”。
2. **可能原因**：终端断电、网络不可达、终端服务未启动、设备正在恢复或终端未上报该设备。
3. **操作人员处理**：检查终端电源和网络指示；确认当前终端选择正确；点击“刷新状态”一次；等待自动复查。
4. **联系技术人员条件**：持续异常/离线，或多个设备同时异常。
5. **提供信息**：检测时间、当前终端、设备卡片名称、卡片提示、刷新结果和对应日志。

### 8.4 抓拍、OCR、IC 卡或虹膜请求失败/超时

1. **现象**：日志出现失败、`timeout`、`busy`，或请求下发后没有最终回调。
2. **可能原因**：设备未就绪、上一次请求未结束、终端回调不可达、网络抖动或队列已满。
3. **操作人员处理**：确认当前终端和设备状态；停止重复点击；等待当前请求明确结束；必要时停止并重新启动对应预览。
4. **联系技术人员条件**：同一功能连续一次重试仍失败、多个功能同时失败、结果归属疑似错误或出现敏感数据异常。
5. **提供信息**：日志时间、终端 1/2、功能名称、点击顺序、请求编号、完整错误提示和是否有保存文件。

### 8.5 预览黑屏、卡顿或启动失败

1. **现象**：预览区域仍显示“未开启”、黑屏、无首帧或日志出现 `preview_failed`。
2. **可能原因**：终端未返回预览地址、VLC 目录不完整、预览配置未启用、网络不可达、窗口句柄已经销毁，或车牌预览未配置。
3. **操作人员处理**：先点击“停止预览”；检查对应健康卡片、终端网络和程序目录；车牌预览先确认项目负责人已提供对应配置；再尝试启动一次。
4. **联系技术人员条件**：摄像头/指纹/虹膜仍无法启动，或车牌预览确认已配置仍失败。
5. **提供信息**：资源名称、当前终端、预览开始和停止时间、日志中的失败码、VLC 目录是否完整、窗口是否刚被关闭/重建。

### 8.6 OCR 没有结果或结果不完整

1. **现象**：点击“OCR 阅读”后没有结果、只有部分字段或没有保存目录。
2. **可能原因**：证件未正确放置、终端回调未到达、请求超时、证件类型/协议数据不完整或保存目录不可写。
3. **操作人员处理**：确认流程已开始、OCR 卡片正常；保持证件稳定；等待当前请求完成，不要重复提交；检查 `captures` 下是否生成 `ocr_result.json`、`MRZ.json` 或证据图片。
4. **联系技术人员条件**：连续一次重试仍无回调，或识别结果与现场证件明显不符。
5. **提供信息**：请求编号、操作时间、当前终端、日志中的 OCR 事件、生成的文件名；证件图片只按授权渠道提供并先脱敏。

### 8.7 授权测试结果异常

1. **现象**：授权下发失败、超时、结果与预期不符或日志数据不完整。
2. **可能原因**：当前按钮使用固定测试参数，终端环境、授权协议或现场配置不匹配。
3. **操作人员处理**：停止再次点击，确认是否处于授权测试环境，保留请求编号和日志。
4. **联系技术人员条件**：任何生产环境误触、重复下发、结果无法解释或疑似把测试请求发到真实业务终端。
5. **提供信息**：操作时间、当前终端、请求编号、授权提示和日志；不得向无关人员发送证件号、姓名等原始数据。

### 8.8 程序无响应或无法退出

1. **现象**：界面长时间不刷新、关闭窗口无反应或退出过程停滞。
2. **可能原因**：终端 HTTP 请求超时、预览播放器正在停止、网络断开或日志/磁盘 I/O 阻塞。
3. **操作人员处理**：等待一段时间并观察日志；不要连续点击；尝试按正常关闭流程选择“退出程序”；若只是想隐藏窗口，选择“最小化到托盘”。
4. **联系技术人员条件**：持续无响应、任务管理器显示 CPU/内存异常，或必须强制结束进程。
5. **提供信息**：最后一次正常日志时间、当前业务/预览、当前终端、窗口截图、程序日志和是否强制关闭。

## 9. 日志与问题反馈

### 9.1 日志位置和命名

- Proxy 日志目录：程序目录下的 `HZCYKJTHardWareExe_Logs`。
- Proxy 日志文件：`HZCYKJTHardWareExe_Logs_yyyyMMdd.log`。
- Proxy 日志按日期切换；程序退出时会尝试刷新待写入内容。
- 日志目录、当前日志文件和紧急回退日志都应作为技术排查证据保留。
- DLL 独立日志可能位于 `HZCYKJTHardWareDLL_Logs`，以实际 DLL 配置和运行目录为准。

### 9.2 反馈问题时应提供

1. 发生时间，精确到秒或毫秒；
2. 程序版本、Windows 版本和 x86/x64 部署信息；
3. 当前终端（终端 1/左通道或终端 2/右通道）；
4. 硬件健康卡片状态；
5. 从启动到异常的实际点击顺序；
6. 请求编号、错误码、完整错误提示；
7. 对应时间段的 Proxy/DLL 日志和生成文件名；
8. 是否切换过终端、重启过服务、关闭过预览或断过网络。

日志可以在获得授权后通过“导出”复制，但发送前必须遮盖证件号码、姓名、卡号、Token、密码、完整 IP 或其他敏感信息。不要把原始日志发送给无关人员或公开群组。

## 10. 安全退出和异常关闭

### 10.1 正常退出

业务结束 → 停止所有预览 → 结束流程 → 确认日志保存 → 停止服务（如需要）→ 关闭窗口并选择“退出程序”。

### 10.2 不允许直接结束进程的场景

- 抓拍、OCR、IC 卡、虹膜或授权仍在等待最终回调；
- 预览仍在显示，且预览窗口即将被销毁；
- 正在切换终端或结束流程；
- 日志中正在写入错误、保存路径或回调结果。

直接结束进程可能导致未完成请求没有最终结果、预览资源未正常释放、日志尾部缺失或终端仍认为流程未结束。

### 10.3 强制关闭后再次启动

由技术人员确认后再重启，并检查：

- 任务管理器中是否仍有 Proxy 实例；
- 监听端口是否已经释放；
- 终端是否仍显示上一流程占用；
- `captures` 是否生成临时或不完整文件；
- 日志中是否有“程序正在退出”之前的错误；
- 是否需要先在终端侧清理上一业务流程。
